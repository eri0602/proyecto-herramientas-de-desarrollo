Mínimo un commit real por persona por semana — nunca acumular todo para el final.

## Pull Requests
Todo merge a `main` pasa por PR, aunque el equipo sea de 2 personas — deja historial de revisión.

Checklist antes de abrir un PR:
- [ ] El código corre sin errores localmente
- [ ] El commit sigue el formato convencional
- [ ] El PR referencia el issue correspondiente
- [ ] No se tocó código de otro módulo sin avisar

## Releases
Tag/release cada 3-4 semanas como hito (ej: `v0.1-semana4`).
